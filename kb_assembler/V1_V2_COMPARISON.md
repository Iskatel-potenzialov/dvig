# Сравнение KB Assembler V1 и V2

| Слой / проекция | V1: проекция после собственного фильтра | V2: исходные записи в проекции |
| --- | ---: | ---: |
| text_bm25 | 32 | 148 |
| text_dense | 32 | 148 |
| passport_dense | 32 | 154 |
| table_dense | 0 | 406 |

В V2 среди 406 R6 сохранены 402 исходных будущих кандидата и 4 заблокированные записи; 185 кандидатов без текстового родителя сохранены. Все исходные `future_candidate`, `runtime_enabled`, условия и статусы присутствуют без переоценки. Ни V1, ни V2 не создали реальный поисковый индекс или embeddings. Полная проекция V2 не является списком разрешённых для runtime фактов.

V1 сохраняется как реализация и сборка для сравнения. V2 механически объединяет все таблицы по составному техническому признаку `bundle_document_id` и исходному ID; условия не используются им как фильтр. Перед реальным поиском отдельная согласованная стадия обязана применить исходные ограничения и проверить применимость; V2 не решает эту задачу.
